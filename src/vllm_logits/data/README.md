# `failure_profiles.csv`: the data behind `python -m vllm_logits.demo`

1,423 failed problem-units from four post-trained models across three tasks. One row per
(model, task, problem). No GPU is needed to use it: every column is already derived.

## Provenance

Generated by running this toolkit's two stages over failed rollouts from the paper
([arXiv:2606.05145](https://arxiv.org/abs/2606.05145)):

1. **`cache_logits`**: per-token specialist to ancestor divergence for every failed rollout of a
   problem, summarised to the three per-problem trajectory features below.
2. **`repair_logits`**: each intervention applied at three attempts per problem, where best-of-3
   defines a rescue, giving the per-problem rescue rate of each operator.

Specialists are Qwen3 checkpoints post-trained on
[Bespoke-Stratos-17k](https://huggingface.co/datasets/bespokelabs/Bespoke-Stratos-17k);
ancestors are the corresponding Qwen3 base checkpoints. Tasks are held-out:
[GSM8K](https://huggingface.co/datasets/openai/gsm8k),
[CruxEval](https://crux-eval.github.io/), and
[GPQA](https://huggingface.co/datasets/Idavidrein/gpqa).

`sft0p6b|gsm8k` is the cell the demo uses for its routing half. Grade-school math is the most legible
task here, and its specialist and ancestor pair (Qwen3-0.6B SFT against Qwen3-0.6B-Base) is the same
family and size as the runnable GPU examples in `examples/`, so the toy and the real result use
comparable checkpoints.

## Columns

| column | meaning |
|---|---|
| `cell`, `model`, `task`, `problem_id` | identifiers |
| `n_failed_rollouts` | failed rollouts this problem contributed |
| `spread` | fraction of trace tokens where the specialist diverged from the ancestor: how *broad* the divergence is |
| `concentration` | `log10(peak / mean)` of the divergence signal: one sharp spike versus diffuse |
| `logit_dispersion` | `log10` variance of the specialist's logits at the junction: how strongly that token responds to a temperature change |
| `retry` | rescue rate of plain resampling |
| `sparse_steer` | rescue rate of sparse logit steering at the detected junction |
| `sparse_steer_random` | same steering strength at a random position (position-selection control) |
| `local_temp` | rescue rate of a local temperature lift at the junction |
| `dense_steer` | rescue rate of steering at every position |

The three feature columns are exactly the inputs `vllm_logits.route()` expects, so this file also
serves as a worked example of the routing input format. Feature definitions with formulas:
[`docs/logit-features.md`](../../../docs/logit-features.md).

## Scope

Rescue rates are measured at three attempts per (problem, operator), a small budget chosen so the
full grid was affordable. Which intervention wins varies by model and task; do not assume the
ordering on one cell transfers to another, or to your own model. Use `--cell` to look at each.
